# ADR-0006: Hashing Policy

- **Status**: Proposed（待批准）
- **Date**: 2026-08-25
- **Deciders**: Nova Chain 架构组
- **Scope**: PHASE 2 — Cryptography

## Context

地址、交易、区块、Merkle/状态承诺、内容哈希需要统一哈希策略。
**不得同一用途混用多个哈希而没有明确理由**（Master Prompt §22 / §25）。

## Decision（建议，待批准）

| 用途 | 哈希 | 理由 |
|------|------|------|
| 协议承诺：address / transaction / block / Merkle / state root | **SHA-256**（统一） | 成熟、SHA-NI 硬件加速、抗长度扩展、审计充分、生态广泛 |
| 链下内容哈希（大文件：音乐/视频/AI 模型） | **BLAKE3** | 并行树形哈希，大文件性能极佳；**仅存摘要于链上，不参与共识承诺**（Master Prompt §34/§35） |

**原则**：
1. 协议内所有承诺**统一使用 SHA-256**——单一协议哈希，减少实现面与审计面。
2. 内容哈希是**链下用途**（独立于共识状态），用 BLAKE3 有明确性能理由，且与协议承诺分离。
3. 禁止同一协议用途同时使用多个哈希（除非经新 ADR 给出明确理由）。

### Protocol Hash Registry（协议哈希注册表）

**以下位置**只能使用 SHA-256，**禁止模块自行切换哈希**（违反视为协议违规）：

| 用途 | 哈希（固定） |
|------|-------------|
| 地址 key_hash（ADR-0004） | SHA-256 |
| 交易哈希 / 交易承诺（PHASE 4） | SHA-256 |
| 区块哈希 / header 承诺（PHASE 7） | SHA-256 |
| Merkle / 状态树承诺（PHASE 5/6） | SHA-256 |
| 状态根 state_root（PHASE 5） | SHA-256 |
| 签名消息 `H(dst‖chain_id‖payload)`（ADR-0005） | SHA-256 |
| 域名分离 DST 相关哈希 | SHA-256 |
| Genesis hash（PHASE 7） | SHA-256 |

- 任何模块需要使用非注册哈希（如性能优化换 BLAKE3）⇒ 必须先提交 ADR 修改本注册表。
- 内容哈希（BLAKE3）**不在**注册表内（链下用途，不参与协议承诺）。

## Alternatives（已评估）

| 哈希 | 评估 |
|------|------|
| SHA-256 | ✅ 协议承诺：成熟、SHA-NI 加速、广泛审计（采纳） |
| SHA3-256（Keccak） | NIST 标准、抗长度扩展；但无 SHA-NI 加速（软件慢）、生态工具较少；不否决，但非默认 |
| BLAKE3 | 极快、树形（适合大文件）；但较新（2020）、无 NIST 认证——**协议承诺保守起见不采用**，仅用于链下内容哈希 |
| BLAKE2b | 性能好、成熟；但协议承诺用 SHA-256 已足够，避免多哈希 |

## Consequences

- **正面**：单一协议哈希降低实现/审计/硬件加速复用成本；内容哈希性能与协议安全解耦。
- **成本**：协议哈希为 SHA-256（非性能最优），但 SHA-NI 使差距可接受；内容哈希需单独规范。
- **可迁移**：协议哈希迁移（如未来换 SHA3）须经新 ADR + 状态树版本化（Master Prompt §25）。

## Security Impact

- SHA-256 抗长度扩展攻击适用于承诺场景（被哈希数据不可变）。
- 注意：SHA-256 是 Merkle-Damgård 结构，**配合 ADR-0005 的定长 DST 前缀**避免长度扩展歧义。
- 内容哈希（BLAKE3）不进入共识状态，其碰撞风险不影响链上安全（仅影响内容寻址可用性）。
- 不声称"量子安全哈希"——SHA-256 当前安全，量子威胁为远期（见 Security Assumptions）。
